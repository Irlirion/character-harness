# Память и оптимизация контекста

## Слои памяти

Рабочее состояние хранит текущую цель и активный навык. Эпизодическая память — попытки и результаты. Семантическая — факты. Процедурная — проверенные стратегии. Обязательства хранят обещания, ограничения и ожидаемые ответы.

Факты имеют источник, область видимости, время, уверенность и срок актуальности. Наблюдаемое, предполагаемое и желаемое состояния различаются. Противоречия разрешаются явно; старые сведения не заменяются молча.

```text
Наблюдение -> кандидат -> проверка -> дедупликация
-> разрешение противоречий -> сохранение
```

Журнал событий — первичная история. Индексы и сводки являются производными данными.

## Сборка контекста

Контекст собирается под очередное решение:

```text
Политика + цель + критерии успеха + состояние
+ активный план + обязательства + существенные события
+ найденная память + нужные схемы инструментов
```

Отбор учитывает релевантность, свежесть, достоверность, последствия пропуска и стоимость токенов. Критические ограничения закрепляются независимо от рейтинга.

В текущем игровом срезе оба движка получают последние десять завершённых пар «сообщение — ответ» до текущего события. Запрос ограничен теми же character и audience, выводится в хронологическом порядке и занимает не более 8 000 сериализованных символов. Текущие, будущие и незавершённые события в историю не попадают. История передаётся модели как недоверенный контекст; автор и provenance остаются явными. Долговременные заметки хранятся отдельно и загружаются через memory tools.

## Механизмы

- Агрегация частых событий вместо включения каждого тика.
- Структурные сводки с фактами, препятствиями и открытыми вопросами.
- Загрузка подробностей по ссылкам при необходимости.
- Выбор ограниченного набора инструментов для текущей задачи.
- Резерв бюджета для ответа и результатов инструментов.
- Кеширование стабильных частей при поддержке модельного API.
- Пересборка контекста при повторных ошибках и отсутствии прогресса.

Сводки сохраняют идентификаторы, обязательства, ограничения, незавершённые действия и доказательства. Их следует восстанавливать из исходных событий и состояния, избегая цепочек пересказов.

Качество оптимизации оценивается по успешности задач и числу пропущенных важных фактов, а не только по сокращению токенов.
