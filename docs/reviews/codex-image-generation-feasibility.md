# Встроенный ImageGen: проверка границы бюджета

Дата: 2026-10-17. Статус: исследование продолжается. После перепроверки найден публичный Rust-клиент прямой генерации; прежний вывод о необходимости менять Codex был преждевременным. Это не реализация генерации в Telegram.

## Проверенный контекст

Рабочий единый Compose использует Codex CLI 0.160.1. `features list` показывает
`image_generation = true`, `hooks = true`, `code_mode_host = true`. Это значения
feature flags, а не доказательство доступности генератора выбранной модели.
Никаких пробных генераций в рамках этого исследования не выполнялось.

В конфигурации harness отсутствовал явный запрет `image_generation`. В этой ветке
добавлено `image_generation = false`, чтобы будущая интеграция не оставила модели
параллельный путь мимо бюджета. Изменение проверено тестом конфигурации; в работающий
Compose эта ветка не развёрнута.

## Основное ограничение

Проверен исходный код точного релиза, а не только текущей основной ветки Codex:

- [PreToolUse в rust-v0.160.1](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/hooks/src/events/pre_tool_use.rs).
- [Регистрация и исполнение инструментов](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/registry.rs).
- [Адаптер штатных расширений](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/handlers/extension_tools.rs).

В `parse_completed` значение `should_block` первоначально равно `false`.
Ошибки выполнения hook, неподдержанный код завершения, некорректный JSON и часть
других ошибок помечают hook как Failed, но не меняют это значение на `true`.
`serialization_failure_outcome` также возвращает `should_block: false`.
Штатный hook допускает продолжение инструмента при части собственных ошибок.

Явный корректный ответ deny и код 2 с объяснением могут блокировать инструмент.
Этого недостаточно для требования спецификации: сбой самого механизма проверки
тоже должен предотвращать расход. Перехват ошибок HTTP внутри нашего скрипта не
покрывает отсутствие скрипта, сбой его запуска, сбой сериализации или недоверенную
конфигурацию hook.

Сгенерирован публичный и экспериментальный TypeScript-протокол установленного
app-server. Отдельного документированного вызова native ImageGen, который harness
мог бы исполнять напрямую после транзакционного резервирования без модельного
цикла, в нём не найдено. Это результат проверки данной версии, а не утверждение
о невозможности такого интерфейса в будущих релизах.

## Дополнительные runtime-пробы и их пределы

В контейнере запущены отдельные эфемерные процессы app-server с отключённым
ImageGen, тестовым dynamic tool без внешних эффектов и собственными hooks.
Установлен hook с явным deny и отдельно hook с ошибкой выполнения.

Оба пробных dynamic tool вызова дошли до callback. Проверка `hooks/list` показала,
что hook присутствует и enabled=true, но trustStatus=untrusted; передача флага
bypass trust не изменила этот статус в выдаче. Проба с CLI-overrides доверия не
завершилась и не считается валидной проверкой доверенного hook.

**Эти пробы не доказывают обход доверенного hook штатным ImageGen** и не используются
как доказательство такого обхода. Основное доказанное ограничение — явно допускающая
продолжение обработка ошибок в коде точного релиза. Для включения нужен успешный
отдельный тест native-пути и всех отказов, включая инфраструктуру контроля.
Содержимое переписки и данные авторизации не выводились; картинки и Telegram-сообщения
в эксперименте не создавались.

## Решение по спецификации

Не включать автономный native ImageGen на основе одного prompt или lifecycle hook.
Не подменять его платным Images API и не писать клиент к закрытому backend с OAuth.
Согласованные лимиты остаются 3 попытки за скользящие 24 часа и 15 за месяц UTC.

Для следующего шага нужен один из следующих технических путей:

1. Поддерживаемый штатный интерфейс прямого исполнения ImageGen, который вызывает
   доверенный исполнитель очереди после атомарной проверки бюджета.
2. Поддерживаемая обязательная проверка до каждого native вызова с запретом при
   сбое, а также возможность исключить обходной путь и проверить это тестами.
3. Собственная поддерживаемая сборка Codex с такой проверкой. Это отдельное решение
   о сопровождении зависимости, сборке, обновлениях и тестировании; в текущем срезе
   такая сборка не создавалась.

До появления проверенного пути блокируются включение генератора и живая приёмка;
не следует объявлять реализованной очередь с несуществующим безопасным исполнителем.

## Выбранный пользователем путь: прямое штатное исполнение

После выбора пользователем первого варианта выполнена дополнительная проверка:
экспериментальный протокол Codex 0.160.1 содержит 170 клиентских методов. Из методов
с Image/Tool/Extension в имени найден `mcpServer/tool/call`; это вызов инструмента
подключённого MCP-сервера, не native ImageGen. Отдельный метод прямой генерации
не обнаружен. В `codex-image-generation/src/lib.rs` точного релиза экспортируется
только `extension::install`; backend и tool являются приватными модулями.

Сверена [официальная документация Image generation](https://learn.chatgpt.com/docs/image-generation)
и [App Server](https://learn.chatgpt.com/docs/app-server). Документация описывает
генерацию через модельный ход Codex и отдельный Images API для программной генерации;
поддерживаемый прямой вызов встроенного генератора через app-server не подтверждён.

Таким образом, первый вариант выбран как желаемый интерфейс, но он не является
доступным готовым способом реализации в проверенной версии. Перечисление его среди
путей решения не должно интерпретироваться как подтверждение существования такого
интерфейса. Реализовать этот путь на неизменённом Codex 0.160.1 сейчас не удалось.

## Исправление после повторной проверки

Предыдущая проверка ограничилась CLI, app-server и экспортами image-generation
extension. Она упустила библиотеку `codex-api` того же официального релиза.

Подтверждено по rust-v0.160.1:

- [`codex-api/src/lib.rs`](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/codex-api/src/lib.rs)
  публично экспортирует `ImagesClient`, `ImageGenerationRequest`, `ImageResponse`,
  `SharedAuthProvider` и остальные необходимые типы.
- [`endpoint/images.rs`](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/codex-api/src/endpoint/images.rs)
  содержит публичный async-метод `ImagesClient::generate`. Он выполняет запрос
  напрямую, без модельного хода.
- Штатный [`image-generation/src/backend.rs`](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/ext/image-generation/src/backend.rs)
  сам использует этот клиент с `provider.api_provider()` и `provider.api_auth()`.
- [`model-provider/src/lib.rs`](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/model-provider/src/lib.rs)
  экспортирует `create_model_provider`, `SharedModelProvider` и адаптеры авторизации.

Следовательно, отсутствие CLI/RPC-метода не доказывает необходимость форка Codex.
Есть конкретный кандидат: небольшой Rust-исполнитель на официальных библиотеках
зафиксированного релиза, который получает задачу только после проверки бюджета.
Прямой доступ модели к генератору при этом остаётся закрыт.

Остаётся проверить сборку такого исполнителя, инициализацию существующей
авторизации через библиотеки Codex, транспортные повторы и доступность Images
для текущей подписки. Публичный Rust-экспорт не означает гарантированного стабильного
внешнего SDK или подтверждённой совместимости будущих релизов. Живую генерацию
через этот библиотечный путь ещё не выполняли. Нельзя объявлять интеграцию готовой
или гарантировать её работу только по наличию метода.

## Итог после изменения приоритета контроля

Пользователь уточнил, что жёсткий контроль каждого native-вызова сейчас не приоритет.
Реализован более простой рабочий путь на существующем TypeScript app-server:
выделенный модельный ход с ImageGen, штатное событие imageGeneration и отправка
через outbox. Настоящий smoke получил PNG 2 760 779 байт с текущим входом ChatGPT,
без API-ключа и без Rust. Очередь ограничивает число запусков задач, а не гарантирует
число внутренних вызовов инструмента. Предыдущий блокер не относится к этому
согласованному упрощённому срезу. Rust-эксперимент остановлен и исключён из рабочего пути.
