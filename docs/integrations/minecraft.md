# Интеграция Minecraft

## Подключение

Mineflayer работает как клиент Minecraft Java Edition и подключается к серверу по игровому протоколу. Для базового сценария серверный плагин не требуется. Версию сервера, режим аутентификации и совместимость закрепляем интеграционным испытанием. Персонаж имеет собственное подключение и игровую идентичность; для online-mode нужны соответствующие авторизованные аккаунты.

## Наблюдения

Worker содержит оперативную модель: координаты, здоровье, голод, инвентарь, видимые сущности и загруженные блоки. Это наблюдаемая часть мира, а не всеведущая карта сервера. Карта и память привязаны к server_id, world_id и dimension.

Нормализованные события: minecraft.spawned, chat_received, health_changed, inventory_changed, danger_detected, disconnected, operation_progress, operation_completed, operation_failed. Проектные названия не являются именами событий Mineflayer: адаптер преобразует его API.

Перед стратегическим решением движок получает краткую сводку. Подробности запрашиваются инструментами; тики и полные чанки не отправляются в LLM.

## Инструменты

```text
minecraft.observe(area, detail)
minecraft.inventory()
minecraft.start_skill(name, arguments) -> operation_id
minecraft.operation_status(operation_id)
minecraft.cancel_operation(operation_id)
minecraft.say(message)
```

Первичные навыки: navigate, collect_resource, craft, eat, deposit_items, build_blueprint. Имена — контракт проекта, реализация ещё отсутствует.

Длительная операция сразу возвращает operation_id. Worker выполняет локальный автомат; прогресс и завершение поступают через журнал. Ожидающая задача пробуждается по событию завершения, а не за счёт бесконечного polling модели.

## Управление и проверка

Перемещение, добыча и строительство получают конфликтующие блокировки. Экстренная остановка имеет приоритет. Pathfinder является механизмом навигации, а не гарантом безопасного поведения: разрешения на ломание/размещение блоков и условия опасности задаёт навык.

Успех определяется инвентарём, положением и фактическими блоками. При disconnect worker перестаёт принимать действия. После подключения состояние сверяется; прежняя операция не считается успешно завершённой автоматически.

Секреты аккаунта находятся в конфигурации адаптера, вне памяти персонажа. Чат игроков считается внешними данными; задачи принимаются по правилам идентичности и полномочий.

Источники: [Mineflayer](https://github.com/PrismarineJS/mineflayer), [Pathfinder](https://github.com/PrismarineJS/mineflayer-pathfinder).

## MCP-интерфейс

Возможности адаптера публикует [общий MCP-шлюз](../mcp-gateway.md). Привязку персонажа и полномочия устанавливает supervisor, а не аргументы модели. События и завершение операций доставляются в core независимо от MCP-соединения.

## Голос

Голосовой вывод через Simple Voice Chat включён в социальный MVP. Предлагается отдельный серверный bridge; см. [голосовую интеграцию](minecraft-voice.md). Для этого пути нужен наш серверный addon/plugin, хотя базовое управление Mineflayer обходится без него.
