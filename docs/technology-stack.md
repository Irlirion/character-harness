# Стек первой версии

Дата: 2026-10-03. Решение проектирования, зависимости ещё не установлены.

## Выбор

| Область | Технология | Причина |
|---|---|---|
| Язык и runtime | TypeScript strict, Node.js 24 LTS, ESM | Общая среда для Pi SDK, Mineflayer и Telegram |
| Репозиторий | pnpm workspaces | Отдельные пакеты с общими контрактами |
| Основной движок | Pi SDK | Прямое управление сессиями, инструментами и ресурсами в TypeScript |
| Дополнительный движок | Codex через EngineAdapter | Подключение после работающего вертикального сценария |
| Интерфейс возможностей | MCP gateway, Streamable HTTP между core и engine | Общие tools для Pi и Codex |
| Контракты | Zod + JSON Schema | Проверка границ IPC, конфигурации и инструментов |
| Хранилище | PostgreSQL, node-postgres, SQL-миграции | Задачи, события, память, операции и транзакционные очереди |
| Поиск памяти | PostgreSQL full-text; pgvector на следующем этапе | Сначала фильтры и текстовый поиск, затем измеренная польза embeddings |
| Telegram | Teleproto + MTProto, пользовательские аккаунты | Общий TypeScript runtime для общения и взаимодействия с ботами |
| Minecraft | Mineflayer + mineflayer-pathfinder | Программный клиент Java Edition и навигация |
| Локальный API | Fastify | Управление экземплярами, health и inspect |
| Логи и трассы | Pino + события решений в PostgreSQL | Связь по character_id, task_id, operation_id, turn_id |
| Проверки | Vitest + реальные интеграционные сценарии | Восстановление, отмена, дубли и проверка результатов |
| Локальная инфраструктура | Docker image для core/engine + Compose; нативные macOS-процессы для локального аудио | Core и engine контейнеризированы; устройство воспроизведения и MLX TTS требуют Mac |
| Мастерская | Отдельные ограниченные Linux-контейнеры | Сгенерированный код не запускается в процессе ядра |

Node LTS проверен по [таблице выпусков](https://nodejs.org/en/about/previous-releases). Версии библиотек фиксируются lockfile при реализации и проверяются вместе; совместимость не предполагается по одному названию версии.

GramJS исключён после проверки: репозиторий архивирован и рекомендует [Teleproto](https://github.com/sanyok12345/teleproto). Поддержку нужных кнопок и восстановление MTProto-сессий проверяем прототипом. PostgreSQL — ветка 18, точные patch-версии закрепляются при реализации.

## Развёртывание

Core и Pi engine запускаются в отдельных Linux-контейнерах, PostgreSQL — отдельным сервисом Compose. Авторизация Telegram выполняется одноразовым контейнером. Данные и сессии живут в volumes. [Спецификация Docker](docker.md).

## Процессы

Core владеет адаптерами и состоянием. Engine находится в отдельном контейнере, не получает DB или Telegram/Minecraft credentials и использует только MCP HTTP. Привязка токена фиксирует персонажа и аудиторию. В первом срезе управление событиями работает через внутренний HTTP API, будущие adapter workers могут использовать IPC внутри core.

События и команды сначала сохраняются в PostgreSQL. Доставка между процессами может быть повторной. inbox/outbox, идентификаторы и leases обеспечивают дедупликацию и восстановление. NOTIFY служит только сигналом пробуждения; периодическая выборка БД восстанавливает пропущенные сигналы. Частые игровые наблюдения агрегируются в worker; в БД записываются значимые события и контрольные точки, а не каждый тик.

Структура планируемая: пустые пакеты пока не создаются. Redis, отдельный брокер, Kubernetes и веб-панель для первой версии не нужны. Распределённый транспорт вводится при переходе на несколько хостов.

## Статус решений

Pi выбран первым движком как инженерное решение для прототипа; пользователь разрешил Pi или Codex. Codex остаётся поддерживаемым направлением, его реализация пока отложена. Пользователь выбрал клиентские аккаунты Telegram для общения и взаимодействия с ботами. Выбран Teleproto/MTProto. Mini Apps требуют отдельного браузерного адаптера.
