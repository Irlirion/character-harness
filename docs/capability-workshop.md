# Мастерская возможностей

Статус: предложенный механизм; исследование Hermes и OpenClaw ещё предстоит.

## Типы результата

1. Навык: инструкция или процедура из существующих действий.
2. Составной инструмент: кодовая обёртка над разрешёнными возможностями.
3. Адаптер: интеграция с новой системой, которая может требовать дополнительных полномочий.

## Жизненный цикл

```text
Нехватка возможности -> контракт и ожидаемая польза
-> поиск существующего решения -> кандидат
-> изолированные испытания -> регистрация версии
-> ограниченное использование -> оценка -> сохранение или откат
```

Мастерская запускается при повторяющихся затруднениях или явной необходимости. Создание инструмента должно оправдывать стоимость разработки и сопровождения.

## Контракт навыка

Входы, предусловия, прогресс, критерии успеха, типизированные ошибки, отмена и правила восстановления. Например, collect_resource завершается по фактическому приросту ресурса в инвентаре.

## Контракт инструмента

Манифест содержит имя, версию, входную и выходную схемы, зависимости, разрешения, таймаут, лимит памяти, тесты и фикстуры. Сгенерированный код выполняется в отдельной изолированной среде, а не в процессе ядра.

Инструмент получает подмножество уже выданных прав. Запрос нового доступа рассматривается отдельно. Зависимости и артефакты фиксируются для воспроизводимости.

## Допуск

Проверяются контракт, сценарии, ошибочные входы, лимиты ресурсов и преимущество перед прежним способом. Неуспешные кандидаты не доступны рабочему планировщику. Версии допускают откат.

Продвижение из личного реестра в общий требует испытаний на разных персонажах и задачах. Авторство, доказательства проверки и история использования сохраняются.
