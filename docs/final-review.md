# Финальное ревью и начало реализации

Дата: 2026-10-04.

## Зафиксированные решения первого среза

- Главная цель MVP — социальный вау-эффект. Событие общения содержит автора, аудиторию и ссылку на реплику.
- Топология: core + отдельный Pi engine + PostgreSQL. MCP между контейнерами через Streamable HTTP. Предыдущий вариант harness/stdio заменён.
- Pi работает через явный customTools → MCP bridge; встроенные shell/fs и discovery ресурсов отключены.
- Одна PostgreSQL, личная память; общий слой — через явную публикацию в последующих срезах. Личные отношения не становятся коллективной биографией.
- Движок получает отдельный контекст аудитории. В первом срезе создаётся новая сессия на событие из разрешённых заметок, без общей сырой истории.
- Управляющие вызовы владельца отделены токеном от engine. Epoch и lease проверяются в транзакции до записи эффекта. Pause отзывает текущий epoch.
- Автоматическое исполнение созданного кода пока выключено. Голос Simple Voice Chat обязателен для социального демо, но не для инфраструктурного среза.

## Результаты субагентов

Архитектурное и ИБ-ревью выявили обход MCP через shell/fs, смешение аудитории в истории движка, недостаточность lease без fencing и отсутствие различения автора поручения и обычного участника. Разработчик предложил разделённые контейнеры, context snapshots и короткие сессии. Продакт перенёс приоритет на социальное взаимодействие. Ресерчер памяти рекомендовал личные записи + явную публикацию в общий слой.

Источники предложений: [продукт](product-plan.md), [реализация](implementation-options.md), [память](memory-options.md). [Независимое ревью Astra](astra-review.md) завершено: рекомендованы совместная сцена «Наше место», отношения через подтверждённые эпизоды и оценка добровольного повторного интереса. Это предложения для следующего среза; параметры пилота ещё не утверждены.

## Что реализовано в коде

Первый срез: Fastify core, stateless MCP HTTP tools agent_get_status/memory_search/memory_propose, PostgreSQL-миграция, дедупликация входящих demo events, сохранение ответов и заметок, pause/resume, fencing epoch, двухминутный lease, максимум три попытки события, отдельный Pi polling worker и Docker Compose.

Это не готовый игровой агент. Нет автоматической интеграции Telegram/игровых событий, STT, scheduler обязанностей, общей публикации памяти, budgets по токенам, streaming речи или runner. Лимит попыток и таймаут turn ограничивают первый demo flow, но не заменяют полноценный бюджет. Процессы engine должны запускаться по одному на binding.

## Проверка

- Четыре локальных теста policy прошли: аудитории/персонажи, paused/stale epoch, invocation conflict, токены.
- docker compose config --quiet прошёл.
- После переключения разрешений Docker доступен. Установлены зависимости и создан pnpm-lock.yaml; Dockerfile использует frozen lockfile.
- Исправлены две ошибки TypeScript; Docker-сборка на Node 24, typecheck и четыре policy-теста прошли.
- PostgreSQL запущен, миграция завершилась с кодом 0. MCP/SQL smoke прошёл на Node 24 в контейнере: разделение owner/engine, дедупликация событий, исключение второй выдачи при активном lease, запись и поиск памяти, повторный invocation и конфликт, pause/resume, запрет старого epoch и сохранение ответа.
- Импорт Pi SDK и создание in-memory session в контейнере проверены. Live Pi не проверен: провайдер, модель и model credential пока не заданы.
- Локальный Node 25 отличается от целевого Node 24; основной путь проверки — Docker.

## Оставшиеся решения

Для голоса: Minecraft loader, версии Simple Voice Chat/Java и TTS. Для пилота: образ персонажа, сервер, тестовые аккаунты, правила допустимых действий участников, связь Minecraft/Telegram identity и бюджет. Эти вопросы не блокируют текущий инфраструктурный срез, но блокируют реальное социальное демо.

## Автоматический голос: второй срез

Добавлены speech_jobs, owner speech API, отдельный audio token, native macOS worker и Swift CoreAudio playback. Пользователь подтвердил слышимость автоматической фразы через Loopback и SVC на сервере. Прошли Docker typecheck/policy tests и speech queue smoke (роль токена, replay/conflict, один claim, отмена/pause, лимит очереди, unknown без повторной выдачи). Инструкция: [audio worker](audio-worker.md).

## Codex и первый игровой цикл

Codex app-server 0.160 запускается с изолированным `CODEX_HOME`, device login через ChatGPT subscription и только ограниченным MCP набором состояния/памяти. Authenticated `model/list` подтвердил точную модель `gpt-6-luna`; выбор модели не переходит к account default, если Luna недоступна. Docker Node 24 typecheck и policy/RPC/model tests прошли. Синтетическое событие прошло реальный Codex turn, сохранило ответ и создало speech job со статусом completed через native audio worker.

Собран client-only Fabric bridge для 1.21.11 / Fabric API 0.141.6 / SVC 2.6.24; server mod не используется. Он передаёт только адресованный игровой текст с UUID из серверного chat context и локально показывает ответ. Отдельный bridge token не даёт доступа к owner/MCP API. Jar и минимальная конфигурация установлены только в `character-harness-test`. Live chat проверка ждёт перезапуска этого экземпляра. UUID не объявляется проверенной личностью, особенно на offline-mode сервере.
