# План до запуска MVP на собственном сервере

Дата: 2026-10-04. Текущий статус: Docker core/PostgreSQL/MCP проверены; реальный модельный turn и внешние адаптеры ещё не проверены. Этот документ задаёт предлагаемые срезы поставки, не календарное обещание.

## Подтверждённое окружение

- Minecraft Java 1.21.11, Fabric; Simple Voice Chat 2.6.24 — подтверждено пользователем.
- Docker работает на Mac. Сервер поддерживает нелицензионный вход; конкретный auth mode для бота надо проверить при подключении.
- Для MVP пользователь хочет использовать подписку Codex; TTS/STT ещё не выбраны.
- Установка server addon не подтверждена. Виртуальный микрофон рассматривается как альтернативный путь, требующий реального Minecraft-клиента с SVC.
- Mineflayer upstream заявляет поддержку 1.21.11; фактический вход и моды сервера проверяются отдельным spike.
- Голосовой transport пока не закреплён. Server addon сохраняет Mineflayer и Docker topology; client-only путь требует отдельного spike и может потребовать клиентского Fabric bridge вместо Mineflayer.

## Целевой результат

Один экземпляр персонажа подключается к существующему Minecraft-серверу, отвечает на обращения в игровом чате, произносит короткие ответы через Simple Voice Chat, приходит к разрешённой точке и сохраняет подтверждённые эпизоды. После перезапуска продолжает знакомство. Его пользовательский Telegram-аккаунт общается в выбранной группе; перенос общей истории разрешён явно. Владелец запускает сервисы через Compose и может остановить инициативу без обращения к модели.

Первый запуск на сервере допускается до готовности Telegram, но полный социальный MVP включает оба канала и голос. Первый пилот использует текстовый вход и голосовой вывод; это не полноценный голосовой диалог без STT.

## Последовательность поставки

### 1. Модельный turn и конфигурация

Выбрать провайдера/модель Pi, проверить реальный ответ через существующий core. Добавить пример конфигурации, проверку обязательных параметров и ограничение вызовов/стоимости для пилота. API-ключи записываются локально в secret-файлы; в чат и журнал не попадают. Выдавать диагностические ошибки без секретов.

Готовность: синтетическое обращение получает ответ модели; pause отменяет запись со старым epoch; ошибка провайдера не создаёт бесконечные попытки.

### 2. Первый работающий Minecraft-персонаж

Отдельный адаптер Mineflayer: подключение, игровой аккаунт, обработка обращения, наблюдение ближайшей сцены, игровой ответ и перемещение к разрешённой точке. Core остаётся источником полномочий. События имеют реального автора, канал и идентификатор; результат действия подтверждается миром. Повтор события не создаёт повторное действие. Автоматическая повторная отправка эффекта с неизвестным результатом запрещена до сверки.

Готовность: на сервере виден персонаж, отвечает и приходит к точке; соединение восстанавливается; оператор останавливает действие. Требуются версия/платформа сервера, адрес, режим аутентификации и разрешённый аккаунт. Проверить совместимость именно с этим сервером.

### 3. Обязательный голос

Совместимый server addon Simple Voice Chat, отдельный TTS-сервис и очередь коротких реплик. Источник аудио связан с сущностью персонажа; очередь проверяет адресата, актуальность и отмену. Голосовые порты и доступ между Docker и сервером конфигурируются явно. Выбор реализации addon зависит от server loader и установленных версий.

Готовность: участник рядом слышит ответ; устаревшая/отменённая реплика не начинается; ошибка TTS не блокирует текстовый ответ и не вызывает дубли.

### 4. Память, Telegram и непрерывность

Добавить эпизоды с источником, участниками и аудиториями; исправление и исключение памяти; открытые обещания. Context assembler отбирает разрешённые релевантные сведения в пределах бюджета. Teleproto-адаптер включает отдельную однократную авторизацию пользовательского аккаунта, сохранение сессии, выбранные чаты, обработку FLOOD_WAIT и дедупликацию. Явная связь Minecraft/Telegram-аккаунтов не даёт автоматического права раскрыть личный факт.

Готовность: после перезапуска персонаж корректно продолжает публичный эпизод в разрешённой группе; исправленная память используется вместо старой; другой человек с похожим ником не узнаётся автоматически.

### 5. Пакет запуска и свободный пилот

Образ персонажа, ограниченные поводы инициативы, общий лимит шума между каналами, режим занятости. Health/readiness реальных адаптеров, preflight-команда, лог причин сбоев и инструкция запуска/остановки/восстановления. Проверить второй пакет последовательно без изменения ядра. Финальный smoke выполняется на выбранном сервере, затем добровольный пилот.

Готовность: Compose запускает персонажа после локальной настройки credentials; нет ручной подстановки ответов; pause работает; после рестарта нет массовой отправки старых сообщений. Пройден полный социальный сценарий и контрольные случаи приватности/повторов.

## Что не блокирует первую поставку

Codex-адаптер, произвольное самокодирование, общий граф знаний, несколько одновременно работающих персонажей и сложное строительство. Контракты сохраняют возможность их добавления. STT поднимается в приоритете, если текстовый вход мешает пилоту.

## Настройка владельцем

Сейчас нужны версия и платформа Minecraft, версия Simple Voice Chat, возможность установить addon, место запуска Docker и названия доступных модельного/TTS провайдеров. Позже: адрес сервера, разрешённый игровой аккаунт, выбранная Telegram-группа и локальная авторизация. Учётные данные не запрашиваются в переписке.

Первый релиз не должен требовать Node/Pi на хосте: только Docker/Compose, конфигурацию, локальные secrets и addon на Minecraft-сервере. Одной команды запуска недостаточно без предварительной авторизации игровых и Telegram-аккаунтов.

## Уточнение модели и голоса

Предлагаемый модельный путь для подписки — официальный Codex app-server с отдельной авторизацией ChatGPT и ограниченным каталогом действий харнеса. Pi остаётся альтернативным engine; существующий Pi worker требует модельный API key и не является готовым subscription flow. Не монтировать весь пользовательский ~/.codex в контейнер: отдельное хранилище авторизации engine. Лимиты подписки остаются ограничением доступности.

Виртуальный микрофон не добавляет голос Mineflayer: аудио должно принимать приложение Minecraft с клиентским SVC. На Mac это native клиент и маршрутизация звука; Linux Docker Desktop не получает такой микрофон автоматически. Для Docker-only решения без server addon рассмотреть отдельный Fabric client bridge в контейнере с headless/display setup, но сначала проверить запуск, звук, вход и API SVC; это новая интеграция, не готовая замена. Возможен native client bridge на Mac при явном изменении требования о полном Docker-развёртывании.

Предлагаемый локальный голосовой baseline: Piper для TTS и faster-whisper multilingual small/int8 для STT на CPU в Docker. Конкретные русский голос, лицензия модели, ARM64 сборка и задержки проверяются spike. Docker на Mac не использует Metal для этих Linux процессов; производительность не обещается без измерений. STT получает аудио из выбранного голосового transport; общий звук виртуального устройства может лишить его надёжной идентификации говорящего. Нужны source UUID из SVC и защита от собственного эха.

## Подтверждённый исходящий voice transport

Пользователь подтвердил слышимость тестовой фразы на сервере через native PrismLauncher instance и Loopback. Для MVP выбранное направление — Docker харнес/engine/сервисы + native Minecraft client и audio worker на Mac; ручной путь уже проверен, автоматический worker ещё не реализован. Server addon не нужен для этого пути. Полная автономность, STT и игровые команды не подтверждены данным тестом.
