# Движки Pi Agent и Codex

Дата проверки источников: 2026-10-03. Статус: архитектурный контракт; адаптеры ещё не реализованы.

## Решение

Использовать Pi Agent или Codex как полноценный агентный движок: сессии, вызовы модели, цикл инструментов и поток событий. Character Harness добавляет персонажей, постоянные цели, память мира, инициативу, адаптеры сред и мастерскую возможностей. Для первой версии выбран Pi SDK; Codex подключается вторым адаптером.

Под Pi Agent предварительно понимается Pi coding agent из проекта earendil-works/pi (ранее badlogic/pi-mono). Если пользователь подразумевает другой проект, конкретная интеграция меняется, внешний контракт остаётся.

## Ответственность

| Область | Владелец |
|---|---|
| Агентный turn, запросы модели, tool loop, история сессии | Движок |
| Личность, биография, отношения, долгосрочные цели | Харнес |
| Отбор внешней памяти и наблюдений для решения | Харнес |
| Компактирование внутренней истории | Движок с координацией харнеса |
| Действия в средах и проверка полномочий | Шлюз инструментов харнеса |
| Быстрые реакции, отмена навыков, блокировки ресурсов | Харнес |
| Кодогенерация кандидатов навыков | Движок в окружении мастерской |
| Испытания, допуск и откат новых возможностей | Харнес |

Не создавать второй конкурирующий tool loop. Исполнение инструмента может запускать длительный навык и возвращать operation_id; завершение навыка становится новым событием. Контроль игрового персонажа не зависит от задержки движка.

## Предлагаемый EngineAdapter

Это интерфейс проекта, а не API Pi или Codex:

```text
capabilities() -> features, limitations, version
openSession(character_context, workspace, tool_bindings) -> session_handle
run(session_handle, decision_input) -> stream<EngineEvent>
interrupt(session_handle) -> status
resume(engine_session_ref) -> session_handle
close(session_handle) -> status
```

Нормализованные события: turn_started, text_delta, tool_started, tool_completed, approval_requested, context_compacted, usage_reported, turn_completed, failed. Адаптер сохраняет исходные события и маркирует отсутствующие метрики как unavailable. Точная поддержка steering, обновления инструментов и управления контекстом описывается capabilities, а не предполагается одинаковой.

## Подключение возможностей

Оба движка используют [общий MCP-каталог](mcp-gateway.md). Для Pi SDK нужно явно настроить MCP-расширение/resource loader: наличие поддержки в CLI не означает автоматическое подключение в SDK. Если закреплённая версия требует bridge, он передаёт вызовы в MCP client и не дублирует бизнес-логику. Реальная поддержка проверяется интеграционным сценарием.

## Pi

Официальный SDK встраивает Pi в Node.js/Bun и предоставляет доступ к сессиям, инструментам и ресурсам. Документация описывает customTools, управление сессиями, abort, события и настройки ресурсов. Предлагаемый путь — SDK в отдельном worker-процессе для каждого экземпляра или группы изолированных экземпляров. Сам SDK не является песочницей.

История Pi сохраняется через SessionManager. Нельзя считать замену массива сообщений достаточной заменой сохранённого контекста. Харнес хранит свою память отдельно и использует поддерживаемые средства создания и восстановления сессий.

Источник: [Pi SDK](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md). Зависимость и её API необходимо закрепить конкретной версией перед реализацией.

## Codex

Официальный SDK поддерживает программное управление локальными threads. Для событий, запросов подтверждения и управления жизненным циклом рассматривается app-server по stdio; это локальный процесс, а не автоматизация окна приложения.

Инструменты мира публикуются через общий MCP-шлюз. Динамические инструменты app-server остаются возможным способом адаптации, но не отдельным каталогом или обходом policy. dynamicTools и соответствующий протокол вызовов экспериментальны. Документация также помечает app-server command и WebSocket как экспериментальные; выбор для эксплуатации требует отдельной проверки закреплённой версии. Нельзя приписывать TypeScript SDK все возможности app-server без проверки.

Источники: [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [Codex App Server](https://learn.chatgpt.com/docs/app-server).

## Изоляция и мастерская

У экземпляра отдельные workspace, ссылки на сессии, память и конфигурация инструментов. Игровому движку выдаётся набор инструментов среды. Кодовый workspace и права разработки предоставляются отдельной сессии мастерской. Глобальные пользовательские навыки и настройки не подхватываются без контроля.

Проверенный навык хранится в каноническом реестре харнеса. Адаптер преобразует его в доступный движку ресурс; не все форматы расширений переносимы. После регистрации обновление сессии выполняется только поддерживаемым способом, при необходимости создаётся новая сессия из контрольной точки.

Смена движка сохраняет биографию и задачи через состояние харнеса. Внутренние истории движков не объявляются взаимозаменяемыми: новая сессия получает структурированную передачу состояния. Старые действия предварительно сверяются со средой.

## Прототип перед выбором

Проверить оба варианта на одной задаче: описание персонажа, пользовательский инструмент, поток событий, отмена длительной операции, восстановление сессии, сжатие контекста и подключение созданного навыка. Pi реализовать первым, Codex проверить на том же сценарии; отсутствие поддержки должно быть явной ошибкой, а не скрытым обходом.
